# task-execute

本仓库编码执行代理。当前任务以 `PROJECT_STATUS.md` 的「进行中 / 下一步」为准，只落地 `tasks.md` 该节仍未勾选项。硬停止、栈、模块名单、反选型只读根目录 `AGENTS.md`，不要在实现里扩写或另立一份。

本技能覆盖默认「可逆本地改动直接做」：未完成【交接确认】、且人类未在交接之后单独说「继续」之前，禁止改任何文件。

权威链禁止自行调和：

1. 行为 / 终态 / Schema / 红线 → `requirements.md` > `design.md`（先读总册 §0.2，再搜 `<!-- §x.y -->` 打开分册）
2. 本次做多远 → `tasks.md` 当前任务那一节（未勾选的不做；37/38 必须用子号）
3. 怎么写 → `docs/standards/`（按层打开，禁止通读 14 篇）
4. 验收对照 → `docs/verification-matrix.md`
5. 常驻硬停止 → `AGENTS.md`（细则不在 AGENTS 扩写）

条款互斥：立刻停笔，写清冲突双方与出处，等人类裁决。禁止静默选边。终态红线 vs「本任务暂不装配」：按任务边界交付，STATUS/PR 写清未接线。

循环：交接确认 → 读规格 → 实现当前勾选项 → 同任务交付测试 → 嘴硬验收 → 更新 STATUS → 停下来等人类。验收通过后禁止自动开下一任务。

## 1. 新会话第一轮：只交接，禁止写代码

交叉读取（只核对，不深改、不编码）：

- `PROJECT_STATUS.md`（当前任务号以这里的「进行中 / 下一步」为准）
- `.kiro/specs/platform-v2/tasks.md` 该任务整节（勾选项 + `_需求：_` / `_设计：_` / `_测试：_`）
- 该节引用的 design 小节（用锚点，不行号）
- `docs/verification-matrix.md` 该任务全部行
- `AGENTS.md` 硬停止
- `git status` / 当前分支 / 未提交 diff

STATUS 与 `tasks.md` / 工作区代码不一致时：以代码和 git 为准，矛盾写进【已知卡点】，不要用过期 STATUS 开写。

有未提交 diff：写进【已知卡点】；禁止切分支、禁止往无关文件继续改。人类未说明如何处置前，视为第 5 节打断。

当前任务本身属于资金 / 会话 / 风控 / 迁移四类时：在【已知卡点】写「需人类确认后才能动」，仍只交接、不开工。

固定回复后停下：

```markdown
【交接确认】
- 当前任务：<编号 + 标题>
- 前置是否齐：<依赖任务号 + 是否已勾选>
- 本任务勾选项：<逐条复述，不扩范围>
- 将打开的规格：<文件 + §>
- 将交付的测试：<矩阵中的类名；没有则写「本任务无属性行」>
- 已知卡点：<STATUS 未决问题 / git 脏工作区 / 四类风险；没有则写无>
- 本轮不做：<边界外的模块 / 表 / 前端 / P1>
```

**授权编码的唯一信号**：【交接确认】发出之后，人类再单独说「继续」（或纠正范围后再说「继续」）。

下面这句**不是**授权编码，即使含「继续」也只触发交接：

> 请先阅读 PROJECT_STATUS.md，确认当前进度、已知问题和下一步，再继续开发。

`/task-execute` 单独出现、或夹在上述第一句里：同样只交接。

本轮已交出【交接确认】、且人类随后单独说「继续」：跳过本节，进入第 2 节。

## 2. 动手前读什么（禁止通读）

交接只交叉核对。人类说「继续」后再按层深读，不要通读 requirements / 整本 design / 全部 standards。`CHANGELOG-*` 不必读。读哪些 standards 以 `AGENTS.md`「动手前读什么」那张表为准：改 POM/模块只读 03；Java 读 01+03+06；写路径/鉴权/审计/会话/evict **只读 05**；HTTP 读 07+09；SQL 读 02；测试读 11；Git 读 08+04。步骤 / 对账 / 风控任务再读对应 `feasibility-*.md`。打开本节 `_设计：_` 列出的分册锚点（先查 `design.md` §0.2）。

写代码前：已在 `task/<n>-<slug>` 则沿用；否则按 `docs/standards/08-git-workflow.md` 新建或切换。禁止 `feat/`、`develop/`。工作区有未提交 diff 时禁止切分支。未获人类明确要求时禁止 `git commit` / `push` / 合入 master。

本机 PowerShell。跑 Maven 前：

```powershell
$env:JAVA_HOME="D:\develop\jdk\jdk-26.0.2"
```

密钥只用 gitignore 的 `deploy/.env`，模板 `deploy/.env.example`（`REDIS_DATABASE=2`）。禁止 Redis db0。本机无 Docker：单测可跑；`*IT` 留 CI。禁止为本地绿改 H2、Embedded Redis，或削弱断言。

## 3. 一次只做一个任务

只实现本节勾选项。禁止顺便做下一任务、一次做完整编组、把后续任务提前做完。

发现自己正在写下一节内容 → 立刻进入第 5 节打断。

## 4. 嘴硬验收（缺一条就保持未勾选）

每个勾选项打勾前必须同时满足。未通过：禁止把 `tasks.md` 勾成 `[x]`，禁止写「本任务完成」。

**规格**：每个新公共 API / 新表 / 新错误码能指回 requirements 或 design 编号；未出现规格没有的字段、状态、端点。写路径涉及鉴权/审计/会话/evict：只以 `docs/standards/05-security.md` 为准。

**边界**：本节勾选项全部覆盖，且没有多做下一节。37/38 只动对应子号。

**测试（最硬）**：

- 测试与实现同任务交付
- 类名必须出现在本节 `_测试：_` 或 verification-matrix 该任务行
- 禁止 `@Disabled`、跳过标签、空测试、只 `assertNotNull` 的假绿
- 本机能跑：`cd server; mvn -q -DskipITs test`（或该模块等价命令），贴关键通过证据
- `*IT`：写明「本机无 Docker，留给 CI」；代码里断言保持完整
- 属性测试（jqwik）必须断言不变量，不只跑一次样例

**反自欺（【验收陈述】里逐条照抄期望答法；答错或含糊 = 未通过）**：

- 未实现行为藏进 TODO / 空方法 / 永远 true 的 if？→ 期望「否」
- 为编译通过改宽模块依赖（域间 Maven 互依、跨域 import Mapper/Entity）？→ 期望「否」
- evict `identity:session`、`new ObjectMapper()`、给门户/internal 加 `@Audited`？→ 期望「否」
- 乐观锁二选一（实体 `@Version` 或 XML `version+1` 一次），且 `rwd_prize` 未加 version？→ 期望「是」（本任务未碰乐观锁 / `rwd_prize` 则写「未涉及」）
- `Result.code` 成功是数字 `0`、失败是字符串？→ 期望「是」（本任务未碰 Result 则写「未涉及」）
- P0 若出现 `ad:position`：只做了命名空间占位（接线是任务 48）？→ 期望「是」或「未出现」

任务结束强制输出，然后**立刻停下**（不要开下一任务）：

```markdown
【验收陈述】
- 做了什么：<对照勾选项逐条>
- 没做什么：<边界外清单>
- 命令与结果：<通过 / 失败 / 因无 Docker 未跑>
- 矩阵行是否覆盖：<是/否 + 类名>
- 反自欺：
  - TODO/空方法/永真 if：否
  - 改宽域依赖：否
  - session evict / ObjectMapper / 门户@Audited：否
  - 乐观锁二选一且 rwd_prize 无 version：是 | 未涉及
  - Result.code 0/字符串：是 | 未涉及
  - ad:position 仅占位：是 | 未出现
- 人类必须看的风险：资金 / 会话 / 风控 / 迁移；命中则写「需人类评审，AI 不得宣称可合」
```

## 5. 【卡点打断】

出现任一情况：立即停止编码。标题用【卡点打断】。只陈述事实、选项、你建议等人拍板的那一项。禁止猜测补全规格、发明错误码、提交半成品并宣称完成。

- 规格互斥，或 feasibility 写了「未列组合 / 禁止静默选边」（例：对账 CALLBACK_FAILED / MANUAL 未进 §5.11）
- 前置任务未勾选，或工作区缺少本任务依赖的模块/端口/表
- 本任务需要 Docker / 现网密钥才能证明，本机做不到，且无法用合法单测替代
- 当前任务**不是**资金 / 会话 / 风控 / 迁移，但改动会碰到：Flyway 已应用脚本、资金账本/库存/积分、会话踢人、风控判定链
- 连续两轮测试失败且根因不明，或准备削弱断言来「先绿」
- 正在做下一任务的内容
- 密钥、密码、真实 `.env` 将进入 git
- 有未提交 diff，且即将切分支或改无关文件

当前任务**本身**就是资金 / 会话 / 风控 / 迁移：不要因为「属于这四类」而拒绝实现。交接时标明「需人类确认」；人类说「继续」后按本节勾选项做完；验收必须写「需人类评审，AI 不得宣称可合」。禁止自审自合。

打断后仍须按第 6 节重写 STATUS。

## 6. 重写 PROJECT_STATUS.md

时机：嘴硬验收通过、被打断、人类要求收工、上下文将耗尽。结合当前代码、git 变更、测试结果核对后**整页重写**，不要追加聊天流水账。阶段事实只写现状；不要把 `AGENTS.md` 变成进度板。

勾选 `tasks.md`：仅当第 4 节通过。只勾本任务本节。勾完后停下，等人类；不要开始下一任务。

结构必须是：

```markdown
# PROJECT_STATUS
> 阶段 / 当前任务号 / 更新日期

## 项目一句话
## 现在做到哪
- 已勾选任务：…
- 进行中：任务 N（哪些勾选项已做、哪些未做）
- 下一步：任务 N 或 N+1（一句话）

## 关键技术决策（本轮新发生的才写）
## 改过的核心文件（路径列表，不要贴大段代码）
## 测试与验证
- 命令与结果
- 矩阵覆盖
- 未跑项及原因

## 已知问题（只写已证实）
## 尝试过但失败的方案（避免下一会话重踩）
## 明确禁止下一会话做的事
## 下一步开发顺序（最多 3 步，带任务号）
```

禁止写入：密码、密钥、连接串口令、聊天争论、未证实猜测、过期「尚未创建」却与仓库不符的句子。
