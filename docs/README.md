## 维护约定

- 用户本次要求确定工作范围；已确认的业务决定维护在 `decisions.md`。代码、迁移、契约与测试说明当前实现，不能把现状自动视为正确需求。
- 开发和检查命令维护在对应工程 README；实际依赖以 POM、package.json 和锁文件为准，不再维护另一份依赖矩阵。
- AGENTS 只放长期有效的仓库约束和常用入口；不要塞入交付日志、历史任务清单或每次都需通读的资料目录。
- 新行为在同批变更中写清验收场景，并同步相关文档、契约与测试。功能变化更新功能清单；不另建全项目进度流水账。
- 测试报告记录版本、命令、环境和结果；文件存在、历史勾选和测试数量不等于当前通过。
- 移动或删除文档时检索引用并检查相对链接。优先更新已有文件，不为每次任务新建一套规格。
