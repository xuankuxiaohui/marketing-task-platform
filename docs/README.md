## 每类信息只维护一处

- 当前阶段、进行中的范围和下一步只写 `PROJECT_STATUS.md`。
- 业务规则放 requirements；技术决策落实到对应 design 章节，未决项放 `decisions.md`。实现偏差写进重构工作项，不能把代码现状直接改成规则。
- 构建文件和锁文件记录实际安装版本，依赖矩阵记录项目选型基线及历史证据。发现不一致时核实后同步，不能靠复制版本表解决。
- 规范写仓库特有约束；工具能检查的格式不重复写多份长清单。AGENTS 只做入口与边界提醒。
- 测试报告须写版本、命令、环境和结果。测试源码或历史勾选仅证明有计划或实现，不能写成“已通过”。

新增文档前先判断是否能更新已有文件。保留稳定需求编号、设计 `§` 锚点和场景编号；移动或删除文件时同步检索引用，检查相对链接。

| 需求/设计 CHANGELOG 两份 | 删除独立版本差异副本；正文保留终态，变更细节由 Git 历史追溯 |
